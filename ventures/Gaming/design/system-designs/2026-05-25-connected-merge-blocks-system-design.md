# 连通数字合并 System Design

## 1. 游戏定位

一款面向浏览器、微信小游戏、抖音小游戏的轻量数字连通合并益智游戏。玩家在固定棋盘上寻找相同数字的横、竖、斜向连通组，点击后合并为更高数字，通过规划合并顺序获得大组收益、连击反馈和更高数字目标。

核心承诺：
- 30 秒内学会：看到相同数字连成片，点一下合并。
- 3-8 分钟一局：无时间压力，适合碎片化休闲和脑力训练。
- 易学难精：短期目标是清出大组，长期目标是合成 2048、8192 或更高。
- 原创表达：复用“八方向连通组点击合并”的玩法机制，不复制竞品名称、视觉、文案、数值表、任务节奏或经济节奏。

暂不做：
- 复杂长线养成、剧情、多角色、多人、排行榜、皮肤商店、赛季活动。
- 传统 2048 的整盘滑动操作。

## 2. 原创主题建议（给 3 个主题，并推荐 1 个）

### 主题 A：星图能量网（推荐）

数字方块表现为星核能量节点。相同数字的连通组合并时，节点汇聚成更高能级星核，棋盘像一张可点亮的星图。

推荐理由：
- 八方向连通天然适合“星座连线”和能量汇聚表达。
- 高阶数字可用能级、光晕、星核大小做区分，不依赖竞品方块视觉。
- 动画反馈空间大：吸附、脉冲、星尘、能量波，低美术成本也能有爽感。
- 数字目标可以包装为“点亮 2048 能级星核”，不需要复杂剧情。

### 主题 B：炼金晶格

棋盘是炼金阵，数字是晶体阶级。相同阶级晶体连通后提炼为更高阶晶体。

优点是合并逻辑直观，色彩和材质容易原创；风险是容易做成偏魔幻或素材需求较高。

### 主题 C：数据花园

数字块是数据种子或叶片，同数连通后生长为更高等级的数据果实。

优点是轻松、亲和，适合女性和休闲用户；风险是数字目标和“2048+”成长感不如星图、炼金强。

推荐采用：主题 A“星图能量网”。MVP 可只做抽象星核、深色网格背景、少量粒子和能级色，不需要角色、剧情或复杂场景。

## 3. 核心循环

单局核心循环：

观察棋盘 -> 找到 2 个及以上相同数字的八方向连通组 -> 点击该组 -> 组内数字汇聚成一个更高数字 -> 空位补入新块 -> 检查新连通组和 Combo -> 继续规划下一次合并。

局内目标：
- 合成当前最高数字。
- 尽量选择更大组，获得倍率收益。
- 利用补块和连通变化制造后续大组。
- 在无可合并组前尽量延长局面。

局外轻循环：

完成一局或任务 -> 获得金币 -> 购买少量道具 -> 下一局挑战更高数字或任务目标。

MVP 不做关卡地图。默认使用无尽单局 + 当前任务 1-3 个，降低内容制作成本。

## 4. 棋盘与基础规则

### 棋盘

MVP 建议：
- 棋盘尺寸：6x6。
- 显示方向：竖屏优先，横屏浏览器居中适配。
- 单格内容：一个数字块，数字取值为 2 的幂，如 2、4、8、16。
- 初始填满棋盘。
- 每次操作后，空位按列补块。

可调参数：

| 参数 | MVP 建议 | 说明 |
| --- | ---: | --- |
| board_width | 6 | 移动端可读性和策略空间平衡 |
| board_height | 6 | 36 格足够形成连通组 |
| min_merge_group | 2 | 至少 2 个相同数字才能合并 |
| starting_values | 2/4/8 | 初局只投放低阶数字 |
| target_value_hint | 2048 | UI 展示的短期目标 |

### 基础输入规则

- 玩家点击任意格。
- 若该格所在连通组大小小于 2，则只做轻微无效反馈，不消耗步数。
- 若连通组大小大于等于 2，则执行合并。
- 一次点击只合并一个连通组。
- 计算和结算必须完全由代码确定，不使用模型或非确定性逻辑。

### 胜负与结算

- MVP 使用无尽局，不设置胜利结束。
- 当棋盘上不存在任何 2 个及以上同数字八方向连通组时，进入“无可合并”状态。
- 无可合并时给玩家选择：使用道具续局，或结算本局分数、最高数字、任务奖励。

## 5. 连通检测与合并规则

### 八方向连通

相邻方向包括：
- 上、下、左、右。
- 左上、右上、左下、右下。

连通条件：
- 数字相同。
- 格子在棋盘内。
- 通过任意八方向路径连接。

实现建议：
- 玩家点击格子后，以该格数字为目标值，用 BFS 或 DFS 搜索同值连通组。
- 每个格子每次搜索最多访问一次。
- 棋盘较小，不需要复杂优化。

### 合并落点

MVP 推荐使用“点击格为落点”：
- 连通组内所有格子向玩家点击的格子汇聚。
- 点击格变为合并后的新数字。
- 组内其他格子清空，等待补块。

选择理由：
- 玩家可控制合并位置，策略更强。
- 易解释，适合触屏。
- 和“最大组中心落点”相比，代码和预期都更清晰。

### 合并数值

基础规则：
- 2 个相同数字合并，至少升 1 阶：2+2 -> 4。
- 组越大，额外收益越高，但不直接按全部数值相加，避免高阶膨胀过快。
- 合并结果由“基础升阶 + 组大小奖励升阶”决定。

公式建议：

```text
base_rank = log2(clicked_value)
result_rank = base_rank + 1 + bonus_rank_by_group_size
result_value = 2 ^ result_rank
```

例如点击 8，组大小为 5，若 bonus_rank 为 1，则结果为 32。

## 6. 原创倍率/收益规则建议（给一版可调参数表）

收益拆成两个部分：合并结果升阶和分数倍率。这样既能让大组有爽感，又能控制高数字生成速度。

### 组大小升阶表

| 连通组大小 | 额外升阶 bonus_rank | 示例：合并 8 的结果 |
| ---: | ---: | ---: |
| 2 | 0 | 16 |
| 3 | 0 | 16 |
| 4 | 1 | 32 |
| 5 | 1 | 32 |
| 6 | 2 | 64 |
| 7-8 | 2 | 64 |
| 9-11 | 3 | 128 |
| 12+ | 4 | 256 |

设计意图：
- 2-3 个组保持基础节奏，不让早期过快跳阶。
- 4 个开始出现明显奖励，鼓励玩家规划。
- 12+ 给强爽点，但在 6x6 棋盘中不常见。

### 分数表

```text
merge_score = result_value * group_score_multiplier * combo_multiplier
```

| 连通组大小 | group_score_multiplier |
| ---: | ---: |
| 2 | 1.0 |
| 3 | 1.2 |
| 4 | 1.6 |
| 5 | 2.0 |
| 6 | 2.6 |
| 7-8 | 3.4 |
| 9-11 | 4.5 |
| 12+ | 6.0 |

参数原则：
- 合并结果影响长期目标。
- 分数倍率影响即时成就。
- 先用这版跑 20-30 局内部测试，再根据“2048 达成率”和“平均局长”调 bonus_rank。

## 7. 补块与死局保底规则

### 补块规则

MVP 推荐按列下落：
- 合并后，组内非落点格变为空。
- 每列已有方块向下落到最低空位。
- 每列顶部生成新方块补满。
- 动画顺序：合并汇聚 -> 消失/升级 -> 下落 -> 新块出现 -> 可操作。

### 新块生成权重

新块只从低于当前最高数字太多的区间生成，避免随机直接送高阶。

MVP 权重：

| 当前最高数字 | 新块候选 | 权重 |
| ---: | --- | --- |
| 最高 <= 64 | 2/4/8 | 55% / 35% / 10% |
| 128-512 | 2/4/8/16 | 45% / 35% / 15% / 5% |
| 1024+ | 2/4/8/16/32 | 38% / 32% / 18% / 9% / 3% |

### 死局保底

目标是减少“刚补完就死”的不公平感，但不让系统明显替玩家作弊。

保底规则：
- 每次补块完成后检查是否存在可合并组。
- 如果不存在，允许系统最多重抽本次新生成块 3 次。
- 3 次后仍无可合并组，则进入无可合并状态。
- 不改动旧块，只重抽本次补入的新块，保持公平边界。

开局保底：
- 初始棋盘生成后必须存在至少 5 个可合并组。
- 初始最高数字不超过 8。
- 初始不生成 10 格以上超大组，避免第一步过强。

## 8. Combo 与爽感反馈

MVP 中 Combo 不需要复杂自动连锁，先定义为“连续有效合并节奏”：

Combo 增长：
- 玩家连续进行有效合并，combo_count +1。
- 无效点击不清空 Combo，只做提示。
- 使用道具后 combo_count 清零。
- 结算或死局清零。

Combo 倍率：

| combo_count | combo_multiplier |
| ---: | ---: |
| 1-2 | 1.0 |
| 3-4 | 1.1 |
| 5-7 | 1.25 |
| 8-11 | 1.45 |
| 12+ | 1.7 |

爽感反馈：
- 2-3 组：轻吸附、短音效、数字弹出。
- 4-5 组：更明显的汇聚轨迹和小粒子。
- 6+ 组：棋盘轻震、能量环扩散、分数大字。
- 9+ 组：短暂停顿 120-180ms，再爆发合成，强化“攒出大组”的回报。
- 产生当前局最高数字时，播放独立升级反馈。

自动连锁可作为后续版本：
- MVP 不做补块后自动合并，避免玩家失去控制。
- 可以只检测“本次补块后新增大组”，用高亮提示，不自动结算。

## 9. 道具系统：撤销、单格清除、重洗

道具目标是救局和降低挫败，不应成为最佳策略。

### 撤销

功能：
- 回退最近一次有效合并。
- 恢复棋盘、分数、最高数字、Combo、任务计数到上一步前。

限制：
- 每局免费 1 次。
- 之后消耗金币或观看激励广告获得 1 次。
- 使用撤销后本次 Combo 清零。
- 不能撤销道具操作，MVP 只记录合并前状态。

开发建议：
- 每次有效合并前保存一个 board_snapshot。
- 只保留 1 步历史，避免复杂栈和经济滥用。

### 单格清除

功能：
- 玩家选择一个格子，将其清空。
- 清空后触发下落和补块。
- 用于打破孤立高阶块或制造连接空间。

限制：
- 每局默认 1 个体验用。
- 不能清除当前最高数字，避免误触和过强。
- 使用后 Combo 清零。
- 清除不会直接得分。

### 重洗

功能：
- 保留棋盘内所有数字值，只重新排列位置。
- 重洗后必须存在至少 1 个可合并组，否则最多重洗 5 次。

限制：
- 每局默认 1 个。
- 不改变数字总量和阶级分布。
- 使用后 Combo 清零。
- 若当前已经无可合并组，可以作为续局手段。

道具购买建议：

| 道具 | 金币价格 | MVP 发放 |
| --- | ---: | --- |
| 撤销 | 80 | 每局免费 1 次 |
| 单格清除 | 120 | 新手第 2 局送 1 次 |
| 重洗 | 160 | 新手第 3 局送 1 次 |

## 10. 任务系统与金币经济

任务只服务于“给玩家当局小目标”，不做复杂通行证。

### 当前任务

MVP 同时展示 1-3 个当前任务：
- 合成 128 或更高 1 次。
- 完成 5 次 4 格以上合并。
- 单局达到 8 Combo。
- 使用 1 次重洗后继续合并 3 次。
- 获得 3000 分。

任务生成原则：
- 优先给自然玩法目标，不强迫玩家低效操作。
- 每局最多刷新 1 个新任务。
- 新手前 3 个任务固定，用于引导机制。

### 金币来源

| 来源 | 金币 |
| --- | ---: |
| 完成一局基础奖励 | 20 |
| 达到 512 | 20 |
| 达到 2048 | 80 |
| 完成普通任务 | 50 |
| 完成进阶任务 | 100 |
| 激励广告双倍结算 | 结算金币 x2 |

### 金币消耗

金币只买三种道具。MVP 不加入皮肤、体力、抽奖或升级。

经济目标：
- 普通玩家每 1-2 局可买 1 个低价道具。
- 道具不能多到每局无脑续命。
- 激励广告只提供补道具或结算翻倍，不影响核心规则。

## 11. 新手引导

引导控制在 60 秒内完成。

第 1 局前 3 步建议：
1. 高亮一组 2 个相连的 2，提示“点击相同连通数字合并”。
2. 高亮一组 4 个相连的 4，提示“大组会合成更高数字”。
3. 合并后展示补块和 Combo，提示“继续寻找相同连通组”。

第 1 次死局：
- 提示“没有可合并组了，可以重洗或结算”。
- 免费给 1 次重洗体验。

第 1 次道具出现：
- 撤销：在玩家合并后出现轻提示，不强制使用。
- 单格清除：在棋盘出现孤立阻塞块时提示一次。
- 重洗：只在无可合并组时重点提示。

引导原则：
- 不遮挡整个棋盘超过 2 秒。
- 不要求玩家记住倍率表，只用“大组更赚”的反馈建立直觉。
- 所有教学文案使用原创表达，不参考竞品页面文案。

## 12. MVP 范围

必须做：
- 6x6 固定棋盘。
- 初始棋盘生成和补块。
- 八方向同数字连通检测。
- 点击连通组合并到点击格。
- 原创组大小升阶表和分数倍率表。
- 下落、补块、死局检查和补块重抽保底。
- 分数、最高数字、Combo。
- 撤销、单格清除、重洗三道具原型。
- 1-3 个当前任务。
- 金币获得和道具购买。
- 简单新手引导。
- 单局结算界面。
- 竖屏移动端适配。

暂不做：
- 复杂关卡地图。
- 排行榜、好友竞争、多人。
- 皮肤商店、抽卡、装饰、剧情。
- 自动连锁合并。
- 每日任务、签到、赛季、成就墙。
- 复杂广告瀑布或商业化 A/B。

## 13. 7 天原型计划

Day 1：
- 实现棋盘数据结构、初始生成、渲染占位。
- 实现八方向 BFS/DFS 连通检测。
- 可点击格子并高亮当前连通组。

Day 2：
- 实现合并到点击格、升阶表、分数计算。
- 实现空位、下落和补块。
- 加入无效点击反馈。

Day 3：
- 实现死局检查、补块重抽保底、单局结算。
- 接入最高数字和基础 UI。
- 跑 20 局检查是否频繁早死。

Day 4：
- 实现 Combo、合并动画、基础音效占位、最高数字反馈。
- 调整 4+、6+、9+ 大组反馈。

Day 5：
- 实现撤销、单格清除、重洗。
- 加入每局道具次数限制和金币购买。
- 验证道具不会破坏棋盘状态。

Day 6：
- 实现任务系统、新手引导、金币结算。
- 固定前 3 个新手任务。
- 加入结算统计：分数、最高数字、最大组、最长 Combo。

Day 7：
- 移动端适配、性能检查、参数调优。
- 内部试玩 10-20 人次或自测 50 局。
- 记录平均局长、2048 达成率、道具使用率和死局原因。

## 14. 微信/抖音小游戏适配

输入适配：
- 全触屏操作，单指点击即可完成核心玩法。
- 格子点击热区略大于视觉块，减少误触。
- 长按可预览连通组，但 MVP 可先用点击后高亮。

版式适配：
- 竖屏优先。
- 顶部：分数、最高数字、金币。
- 中部：棋盘。
- 底部：撤销、清除、重洗、当前任务入口。
- 结算弹层不使用复杂滚动内容。

性能适配：
- 棋盘 36 格，动画对象数量少。
- 粒子效果限制在大组合并和最高数字升级时播放。
- 道具和任务逻辑本地即可完成。

平台商业化预留：
- 激励广告入口：道具不足、死局续局、结算翻倍。
- 插屏广告：MVP 可预留结算后触发点，但原型阶段可不接。
- 分享：可在结算页分享“本局最高数字”，但 MVP 不依赖分享裂变。

合规和体验：
- 避免诱导分享才能继续。
- 避免把失败强绑定广告。
- 首局不弹广告。

## 15. 侵权风险规避清单

必须避免：
- 不使用“2048 Merge Blocks”或近似名称作为游戏名。
- 不使用竞品 Logo、图标、页面布局、按钮样式、广告素材、截图或宣传语。
- 不复刻竞品配色、字体、块样式和特效节奏。
- 不照搬竞品具体数值表、任务顺序、金币价格、道具发放节奏。
- 不复制竞品 UI 文案，包括按钮、任务、引导、结算描述。
- 不复刻竞品关卡或初始棋盘布局。

可以保留的机制抽象：
- 数字方块。
- 相同数字连通组合并。
- 八方向连通。
- 合成更高 2 的幂数字。
- 撤销、清除、重洗这类通用益智道具。
- 分数、Combo、任务、金币等通用休闲游戏结构。

原创表达要求：
- 使用“星图能量网”或其他原创主题包装。
- 重新设计色彩、块形、动画、音效和文案。
- 使用本文自定义的倍率、补块、任务和经济参数。
- 任务命名围绕原创主题，例如“点亮 4 次星链”“凝聚 512 能级”。

## 16. 验证指标

原型目标不是证明长期商业化，而是验证核心玩法是否成立。

核心玩法指标：
- 新手第 1 局完成率 >= 90%。
- 玩家能在 60 秒内理解“相同连通组点击合并”。
- 平均单局时长 3-8 分钟。
- 首局达到 128 的玩家比例 >= 70%。
- 试玩 5 局内达到 2048 的玩家比例在 20%-45% 之间。

策略和爽感指标：
- 每局 4 格以上合并次数 >= 8。
- 每局 6 格以上合并次数 >= 2。
- 玩家主动为大组保留位置的定性反馈明显。
- 最大组反馈被玩家注意到，且不觉得拖慢节奏。

公平性指标：
- 因补块后立即无路可走导致的结算占比 <= 15%。
- 玩家对“随机不公平”的主观抱怨低于主要问题前三。
- 重洗使用后继续操作次数中位数 >= 5。

经济和道具指标：
- 每局平均道具使用次数 0.5-1.5。
- 撤销使用率高于单格清除和重洗，但不超过每局 1 次平均。
- 道具不足时激励广告意愿可观察，但 MVP 不以广告收入为判断核心。

留存意向指标：
- 试玩后愿意再开一局的玩家比例 >= 60%。
- 玩家能说出自己下一局想改进的策略，例如“先攒大组”“别急着合并高数字”。
- 主要负反馈不集中在“看不清数字”“不知道为什么得分”“道具太强或太弱”。
