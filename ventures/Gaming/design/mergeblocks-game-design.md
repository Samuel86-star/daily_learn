# 星图能量网 (Merge Blocks) — 游戏设计文档

> 最后更新：2026-06-08
> 版本：v4.0
> 技术栈：PixiJS v8 + Vite + WebAudio

---

## 1. 游戏概述

### 1.1 一句话定义
**点击棋盘上同色连通块，合并为更大数字的 6×6 消除策略游戏。**

### 1.2 核心体验
- 发现棋盘上的同色连通区域
- 一次点击即合并全组（无需拖拽）
- 取舍"现在合并小赚一笔"vs"等更大组爆发"
- 任务驱动目标感，金币驱动循环

### 1.3 差异化 vs 传统 2048
| | 传统 2048 | 星图能量网 |
|---|---|---|
| 操作 | 方向键滑动 | 单击同色连通组 |
| 合并逻辑 | 同行/列同值 | 八方向 BFS 连通 |
| 棋盘大小 | 4×4 | 6×6 |
| 核心策略 | 方向规划 | 组大小取舍 + 组形状培育 |
| 目标 | 达到 2048 | 任务驱动 + 死局结束 |

## 2. 核心玩法机制

### 2.1 连通组检测（八方向 BFS）

```
邻接方向：↖ ↑ ↗  ← · →  ↙ ↓ ↘（8 方向）

触发条件：同值格子以任意方向相邻 ≥ 2 个
点击后：BFS 搜索全组 → 组内所有格子飞到落点 → 升级
```

**设计意图**：八方向连通比四方向更灵活，降低了"找不到可合并组"的挫败感，同时增加了"培育大面积同色区域"的策略深度。

### 2.2 合并公式

```
resultRank = baseRank + 1 + bonusRank
resultValue = 2 ^ resultRank

bonusRank = f(groupSize):
  2-3 块 → +0（无 bonus，2个2合为4）
  4-5 块 → +1（4个2合为8）
  6-8 块 → +2（6个2合为16）
  9-11 块→ +3
  12+ 块→ +4
```

**设计意图**：组越大，升级跳级越多。鼓励玩家"忍住不点"等更大组形成。

### 2.3 分数系统

```
单次得分 = resultValue × scoreMultiplier × comboMultiplier

scoreMultiplier = f(groupSize):
  2块→×1.0   3块→×1.2   4块→×1.6   6块→×2.6   12+→×6.0

comboMultiplier = f(连续合并次数):
  1-2次→×1.0   3-4次→×1.1   5-7次→×1.25   8-11次→×1.45   12+→×1.7
```

**设计意图**：双重乘数（组大小 × 连击）使得"先攒大组 → 连续收割"是最佳策略。

### 2.4 补块规则

- 每次合并后：同列格子**重力下落**，顶部补齐随机新块
- 新块权重随棋盘最高数字动态调整：
  - 当前最高 ≤64：70% 出 2，20% 出 4，10% 出 8
  - 当前最高 ≤512：45% 出 2，35% 出 4，15% 出 8，5% 出 16
  - 当前最高 >512：38% 出 2，32% 出 4，18% 出 8，9% 出 16，3% 出 32
- 死局检测：合并后若无任何可合并组 → 尝试重 roll 新块 3 次 → 仍无 → game over

### 2.5 初始棋盘生成

- 6×6 全满（36 格）
- 种子值：2, 2, 2, 2, 4, 4, 8 + 随机补满
- 保证 ≥5 个可合并组 + 最高数字 ≤8
- 不满足时重新生成（最多 20 次尝试）

## 3. 任务系统（Quest System）

### 3.1 设计理念

任务 = 本局游戏的**阶段性目标**，不是永久成就。

- 最多同时显示 **3 个**任务卡片
- 完成一个后**自动补新任务**
- **3 个全完成时触发胜利结算**（"🏆 目标全部达成"）

### 3.2 任务类型（10 种模板）

| ID | 描述 | 类型 | 检查条件 | 奖励 |
|----|------|------|---------|------|
| `reach_128` | 合成 128 | 里程碑 | `maxTile ≥ 128` | 50✦ |
| `reach_512` | 合成 512 | 里程碑 | `maxTile ≥ 512` | 100✦ |
| `reach_2048` | 合成 2048 | 里程碑 | `maxTile ≥ 2048` | 100✦ |
| `big_merge_4` | 完成 5 次 4 格以上合并 | 累积 | `bigMergeCount4 ≥ 5` | 50✦ |
| `big_merge_6` | 完成 3 次 6 格以上合并 | 累积 | `bigMergeCount6 ≥ 3` | 100✦ |
| `combo_8` | 单局达到 8 Combo | 里程碑 | `maxCombo ≥ 8` | 100✦ |
| `score_3000` | 获得 3000 分 | 里程碑 | `score ≥ 3000` | 50✦ |
| `score_10000` | 获得 10000 分 | 里程碑 | `score ≥ 10000` | 100✦ |
| `shuffle_use` | 使用重洗后继续合并 3 次 | 条件 | `shuffleUsed && mergesAfterShuffle ≥ 3` | 50✦ |
| `merge_10_times` | 合并 10 次 | 累积 | `totalMerges ≥ 10` | 50✦ |

### 3.3 任务刷新逻辑

```
update(stats):
  for each active quest:
    if not completed && check(stats):
      mark completed
      fire onComplete(quest) → add coins
  
  if all 3 active quests completed:
    set gameOver = true, victory = true
  else:
    fillQuests() → 从未分配的模板中随机补到 3 个
```

## 4. 经济闭环

### 4.1 模型

```
┌─────────────────────────────────────────────────────┐
│               星图能量网 经济闭环                      │
│                                                     │
│   完成合并 ──→ 完成成就/任务 ──→ 获得金币 ✦           │
│       ↑                              │              │
│       │                              ↓              │
│   道具助力                    金币购买道具             │
│   (撤销/消除/重排)           (道具次数用完后)          │
│       │                              │              │
│       └──────── 使用道具 ─────────────┘              │
└─────────────────────────────────────────────────────┘
```

### 4.2 金币收支

| 来源 | 数量 | 触发条件 |
|------|------|---------|
| 任务完成 | 50✦ / 100✦ | 取决于任务类型 |
| 局末结算 | 20✦ | 每局固定 |
| 局末结算 bonus | +20✦ | 达成 512 |
| 局末结算 bonus | +80✦ | 达成 2048 |

| 消耗 | 数量 | 条件 |
|------|------|------|
| 购买撤销 | 80✦ | 免费次数用完后 |
| 购买消除 | 120✦ | 免费次数用完后 |
| 购买重排 | 160✦ | 免费次数用完后 |

### 4.3 道具免费配额

| 道具 | 每局免费次数 | 金币价格 |
|------|------------|---------|
| 撤销 | 1 次 | 80✦ |
| 消除 | 1 次 | 120✦ |
| 重排 | 1 次 | 160✦ |

**设计意图**：每局送各 1 次免费，让玩家体验道具价值；用完后金币购买，形成"完成任务 → 赚金币 → 买道具 → 更容易完成任务"的正循环。

## 5. 游戏结束条件

| 条件 | 类型 | 结算画面 |
|------|------|---------|
| 棋盘无任何可合并组 | 死局 | "本局完成"（标准结算） |
| 3 个本局目标全完成 | 胜利 | "🏆 目标全部达成" |

### 5.1 结算统计

- 最终分数
- 最高数字
- 合并次数
- 最高连击（≥3 时显示）
- 获得金币

## 6. 音效系统（WebAudio 程序化合成）

无外部音频文件，全部由振荡器 + 包络实时生成：

| 事件 | 音效 |
|------|------|
| 点击合并 | 短促 sine tap（800Hz, 40ms） |
| 合并升级 | 三角波扫频（按值五声音阶）+ 和声五度 |
| 连击 | 递增音高（600Hz + combo×80Hz） |
| 无效点击 | 低沉 square dud（180Hz, 100ms） |
| 大组爆发 | 多音上行琶音 + 白噪声击打 |
| 任务完成 | C5-E5-G5 上行三音 |
| 游戏结束 | A4-F4-C4 下行三音 |
| 道具使用 | 440→880Hz sine 扫频 |

## 8. 动画系统

### 合并时间线（~800ms 总时长）

```
阶段 1: 吸附 (200ms)
  ├─ 被吸组内格子弧线飞向目标
  └─ 目标格轻微震动

阶段 2: 升级 (320ms)
  ├─ 落点弹性缩放 (0.7 → 1.0)
  ├─ 白色闪光淡出
  └─ 轻微冲击波环扩散

阶段 3: 下落 (250ms/列)
  ├─ 同列空隙重力下落 + 落地弹跳
  └─ 列间错峰 (coll * 18ms)

阶段 4: 补块 (250ms)
  └─ 新块从顶部滑入 + 弹性缓出

阶段 5: 飘字
  ├─ +N 分数上浮 (黄色)
  └─ Combo ×N 上浮 (青色)
```

### 反馈效果

| 操作 | 动画 |
|------|------|
| 选中组 | 黄色光环 + 放大 1.06x |
| 无效点击 | 水平抖动 |
| 分数变化 | 数字上跳 + 金色闪烁 |
| 连击显示 | 卡片内角标淡入 |
| 任务完成 | ✓ 变绿 + 金币飞向右上角 |
| 全部目标完成 | 金色大字飞入庆祝 |

## 9. 技术架构

```
src/
├── main.js              # 入口：初始化 PIXI、连线各模块
├── game/
│   ├── config.js        # 所有常量：棋盘/分数/道具/颜色
│   ├── Board.js         # 棋盘数据结构 (6×6 grid of Tile)
│   ├── Tile.js          # 单个数字块 (value + id + isNew)
│   ├── MergeEngine.js   # BFS 连通检测 + 合并执行
│   ├── BoardFiller.js   # 初始生成 + 重力下落 + 死局恢复
│   ├── GameState.js     # 中央状态：tap() 返回动画时间线
│   ├── ComboSystem.js   # 连击计数 + 倍率
│   ├── QuestSystem.js   # 任务模板 + 激活/完成/刷新
│   ├── Economy.js       # 金币增删
│   └── ItemSystem.js    # 道具管理（撤销/消除/重排）
├── render/
│   ├── UIManager.js     # 所有 UI：信息卡/任务面板/道具/结算/购买弹窗
│   ├── BoardRenderer.js # 棋盘背景网格
│   ├── TileRenderer.js  # 数字块渲染（3D 浮雕 + 糖果色）
│   ├── AnimationManager.js # 合并时间线播放器
│   ├── BackgroundRenderer.js # 动态星空背景
│   └── InputHandler.js  # 屏幕坐标 → 棋盘局部坐标
├── audio/
│   └── SoundManager.js  # WebAudio 程序化音效
└── tutorial/
    └── TutorialManager.js # 新手引导系统（localStorage 持久化）
```

**核心设计模式**：
- `tap(row, col)` 返回完整动画时间线 → 渲染层纯播放，无游戏逻辑
- `UIManager` 通过 `setOnXxx` 回调与外部通信，不直接操作 GameState
- 所有坐标基于 430×932 设计稿 + 统一 scale 缩放适配
